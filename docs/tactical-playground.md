分支：`codex/tactical-playground`。这是独立试玩原型，保留四人、固定成长、8级上限、歼灭目标与战后全恢复。正式战役默认内容不变。

## 评价原则

优先判断是否出现不同的目标优先级、行动顺序、走位和队友配合。脚本通关不作为真人乐趣结论。固定种子只固定初始条件；行动分支不同会改变随机数消耗，不声称两种打法拥有逐骰相同的运气。

## 试玩

```powershell
.\run-tactical.ps1                          # 铸场，3级
.\run-tactical.ps1 -Encounter archive       # 书库，4级
.\run-tactical.ps1 -Encounter sanctum       # 圣所，7级
.\run-tactical.ps1 -Encounter sanctum -Baseline  # 原场景与原装备
.\run-tactical.ps1 -Encounter sanctum -NoGear    # 新场景、原装备
```

默认阵容：战士/游荡者/法师/牧师；种子42。支持 `-Seed 7`、`-UI plain`。等级按正式战役进入对应关卡时的等级设置，不用满级碾压早期关卡。每次启动创建独立临时SQLite，显示恢复命令；不会打开正常玩家数据库。`q`随时退出，战败可重试，胜利后11号沿用当前装备重新演练。重新演练使用当前RNG状态；严格比较初始种子应重新运行同一启动命令。

想用武僧或其他阵容，可用底层入口：

```powershell
.\.venv\Scripts\python.exe -m tools.dev_play --encounter archive --level 4 --classes fighter,monk,wizard,cleric --tactical --tactical-gear
```

只比较装备时保留 `--tactical-gear`、去掉 `--tactical`。只比较场景则相反。`--equip` 可覆盖自动配装。

## 规则与取舍

| 场景 | 新规则 | 可尝试的选择 |
| --- | --- | --- |
| 铸场 | E6熔流闸，相邻且视线连通，消耗一个动作。开启立即对H5/H6/H7占位者造成6火焰伤害，随后每次进入同样受伤；关闭恢复原危险地面。不会每回合自动烧伤静止者。 | 抢先开闸迫使绕路、等敌人进入再开、让自己近战先过、直接强攻。机关不阻挡视线。 |
| 书库 | E1移至L8保护修复师E4；3米且视线连通时，用正常反应抵消修复师下一次伤害中的6点。护卫保持近处阵位，仍会攻击近身队员；修复师倒下后恢复普通追击。 | 消耗反应、震慑卫士、逼修复师离开保护范围、优先处理卫士或直接集中火力。 |
| 圣所 | H3烈焰祭坛使3米且视线连通的敌我武器命中+2原类型伤害；H9庇护祭坛使同范围敌我每次伤害-3。相邻消耗一个动作可永久摧毁。 | 夺取有利区域、把敌人引离区域、绕行，或花动作摧毁。法术不受烈焰增伤。 |

所有场景仍以歼灭获胜，没有强制倒计时或公开敌人未来行动。祭坛/机关是已知公共地形；隐藏单位身份、位置和其伤害事件仍经过可见性过滤。新增规则为项目原创，未声称是BG3规则复刻。

| 装备 | 效果与约束 | 明确放弃的收益 |
| --- | --- | --- |
| 截击盾 | AC+2；具备盾牌熟练者借机命中后，敌人本回合剩余移动归零。仍消耗正常反应，不阻止敌人攻击，不额外增加反应。 | 占用副手，不能持双手武器；相较堡垒盾少1AC。 |
| 撤步靴 | 自己回合成功偷袭后，菜单开放一次额外至多3米撤步，不消耗正常移动、不触发借机。按实际路径验证，危险地面照常结算，未使用则下回合失效。 | 占用鞋位，没有常驻移动或豁免加成；必须具备偷袭。 |
| 守护指环 | 三种指定治疗法术实际治疗其他队友后，给予下次正伤害-3；至施术者下一回合开始失效，不叠加、不刷新。 | 占用戒指位，不增加治疗量、AC或法术DC；满血、自疗、救助、药水不触发。 |

伤害先结算抗性/免疫，再依次结算庇护祭坛、护卫反应、治疗守护，最后结算临时生命。前一层已抵消全部伤害时，不消耗后一层。普通伤害骰不因这些减伤多掷或重掷。

实验装备仅由独立开发局提供，没有加入正式战役商店和掉落。装备效果、机关状态、待选反应均由正常核心结算并持久化；支持重开普通客户端恢复。实验局使用 `0.9.0-tactical-lab` 版本标记，旧主线代码会拒绝解释该版本；正常无实验装备的战役仍使用原版本。

## 对照与已知局限

2026-10-30运行：2阵容（混编/经典）、3场景、2种子（7/42）、5组合，共60场，60场完成，单场4–6回合。组合包括原版、仅场景、仅装备、两者同时、两者同时并使用机关/辅助策略。

脚本只通过玩家可见状态和正式预览选择行动。辅助策略会尝试一次开闸或摧毁庇护祭坛、优先处理可见修复师、使用祝福/震慑，并在偷袭后向队友撤步。它不是最优解；该策略比较同时改变了多项行为，不能将收益单独归因于某一机关。

实际记录：撤步使用5次、治疗守护授予7次、可见减伤累计185点（祭坛/护卫/守护合计）。截击盾在本轮脚本中未触发，其命中截停、放弃反应与移动恢复已由专项测试验证，但自然遭遇中的使用频率仍需人工验证。

初步判断：

- 原进攻策略仍能完成实验遭遇，机关没有变成强制操作。
- 熔流策略有真实机会成本；混编seed7原版4轮/损失3HP，实验辅助策略5轮/损失22HP。不能把“有新按钮”直接当成优化。
- 混编圣所seed42原版4轮/损失135HP，实验辅助策略4轮/损失59HP；这是单样本、不同策略与RNG路径的观察，不是平衡结论。
- 单独换装备的进攻脚本没有表现出回合数变化。撤步需要主动选择，截击需要主动贴近会撤退的敌人；装备是否足够吸引人需要试玩。
- 没有真人完整试玩结论，也没有证明五小时战役节奏或重玩欲望提升。下一轮应优先记录：是否愿意花动作开闸、祭坛留/拆是否存在稳定唯一解、截击盾是否有自然发挥机会。

可复现命令：

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_tactical_playground.py
.\.venv\Scripts\python.exe -m tools.audit_tactical --parties mixed classic --trace --output .qa/tactical-audit.json
```

汇总：[tactical-audit-summary.json](tactical-audit-summary.json)。完整逐动作记录在被Git忽略的 `.qa/tactical-audit.json`，不依赖最多100条的游戏内事件尾部。指标包括首次接敌回合、行动分布、移动、机关操作、触发、可见伤害与最后一名敌人存活涉及的回合数；最后一项不是精确“垃圾时间”。
