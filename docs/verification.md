## 中文终端交互验收

`tests/test_terminal_menu.py` 使用真实规则和 SQLite 验证首页四职业的全部技能入口、不可用技能原因、中文目标选择、治疗、多目标祝福、移动成本和剩余移动一致性、结束后切换队员、取消、列表和预览过期、反应恢复、战败重试及战后短休。

其中两项启动独立的 `python -S -u -m client` 进程，通过标准输入输出读取每层真实提示。默认四职业、种子 42 的终端战斗仅输入编号、坐标、`c`、`0`、`q`，在检查遮挡目标、数字不能确认、返回取消和另一个连接造成预览过期后继续至胜利，并完成短休。另一项从已保存反应窗口启动新进程，查看命中率、返回重新选择，再确认放弃反应。测试把终端输出与输入记录保留在 pytest 临时目录中。

真实 HTTP 回环测试同样使用编号菜单和 `c`，通过标准库 urllib 获取目标与可达范围；第 10 次提交后重启服务并继续至胜利。菜单数据与预览纯读测试确认状态和随机数未改变，隐藏目标未进入选项。地图测试验证每格为 3 个 ASCII 字符并以竖线分隔，16 列地图行宽 69 字符，中文说明按显示宽度折行。

试玩反馈的回归覆盖实际地图 K4/L4 的水平距离与高差、死亡敌人与队员同格时不再覆盖队员、遗体所在格恢复原地形及可达标记、死亡敌人从攻击目标中移除。三维射程计算保持原规则，目标菜单增加中文方向及高差说明。

`tests/test_battle_end.py` 的 8 项战后测试验证全队短休只需一次确认、逐人恢复预览与执行一致、倒地救起但不复活死者、不恢复法术位和药水、次数用尽、取消和过期预览；重开保留原周目与职业阵容，创建回执丢失后复用原命令编号恢复。另一真实标准库终端进程从实际战斗产生的胜利存档进入结算，查看战利品说明、取消并确认全队短休，再取消并确认新周目，核对旧档与客户端配置。当前切片没有下一关和可拾取掉落，菜单明确说明。

策略脚本只为测试挑选行动；上述终端进程验证不等同于人工体验评估。

## 本轮审查修复

- 多个牧师的祝福保留独立来源；效果只加一个 d4，一方结束专注不移除另一方仍有效的来源。
- 敌人按可知信息绕开倒地队员的占格，不重复选择被阻塞的最短路。
- 小写位置无法绕过墙体验证；终端统一转换为大写，API 要求规范位置。
- 隐藏射手发起攻击前显形，再生成可见日志。
- 职业豁免熟练与闪避的敏捷豁免优势进入实际结算和概率预览。

尚未验证指定 BG3 build 的规则一致性、家中到公司的网络、系统开机自启、完整战役人工试玩或五小时节奏。自动走通只证明当前切片的规则与恢复流程能够完成，不能替代计划书 M3–M5 的验收。
